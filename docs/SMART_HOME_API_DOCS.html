01 · Boot sequence

Getting Started

Run the backend near your Home Assistant instance. Keep the API thin: HTTP routes call services; services call Home Assistant through the low-level client.

Prerequisites

Docker or Docker Compose, Home Assistant running on the LAN or localhost, Python 3.11+, and a Home Assistant Long-Lived Access Token.

Runtime

The backend runs as a FastAPI process from D:\smart_home\backend or /mnt/d/smart_home/backend.

Control path

Hermes automation should prefer POST /commands; direct device endpoints are useful for manual API clients and testing.

Docker Compose snippet

docker-compose.yml
services:
  smart-home-api:
    build: ./backend
    container_name: smart-home-api
    restart: unless-stopped
    environment:
      HA_URL: http://homeassistant:8123
      HA_TOKEN: ${HA_TOKEN}
      HA_TIMEOUT_SEC: 10
    ports:
      - "8000:8000"
    depends_on:
      - homeassistant

  homeassistant:
    image: ghcr.io/home-assistant/home-assistant:stable
    container_name: homeassistant
    restart: unless-stopped
    network_mode: host
    volumes:
      - ./config:/config

Environment variables

NameRequiredExampleDescription
HA_URLYeshttp://localhost:8123Home Assistant base URL. This is the preferred key.
HA_TOKENYes[REDACTED]Home Assistant Long-Lived Access Token. Never commit it.
HA_TIMEOUT_SECNo10HTTP timeout for HA REST calls.
HASS_*Nocommented outBackward-compatible fallback only. HA_* wins when both exist.

02 · Secure channel

Authentication

Home Assistant uses bearer tokens for REST API access. Store the token in the backend environment; do not paste real tokens into docs, source files, or chat logs.

Generate token

  1. Open Home Assistant.
  2. Go to your user profile.
  3. Scroll to Long-Lived Access Tokens.
  4. Create a token named smart-home-api.
  5. Copy it once and put it in backend/.env as HA_TOKEN.

Bearer header

When testing Home Assistant directly, pass the token as:

header
Authorization: Bearer [REDACTED]
Content-Type: application/json
curl with auth
curl -sS http://127.0.0.1:8000/ha/health \
  -H "Content-Type: application/json"

03 · Interface contract

Endpoints Reference

These docs show a clean device-control surface for API consumers. For Hermes automation in the current backend, POST /commands remains the canonical production path.

Implementation note: Some direct control routes below are developer-friendly aliases from the requested documentation prompt. If an alias is not implemented yet, route the same behavior through POST /services/{domain}/{service} or POST /commands.

04 · Domain support

Supported Entity Types

Entity support maps to Home Assistant domains. Verification is strongest for binary on/off states and should be explicit for richer domains like climate or cover.

DomainSupported actionsNotes
lightturn_on, turn_off, toggle, setSupports brightness, RGB color, and color temperature when hardware supports it.
switchturn_on, turn_off, toggleClean on/off verification.
coveropen_cover, close_cover, stop_coverMay need explicit expected state or position checks.
climateset_temperature, set_hvac_modeVerification should check attributes like target temperature or HVAC mode.
sensorreadUsually read-only; do not send service calls unless using custom integrations.
input_booleanturn_on, turn_off, toggleUseful for virtual automations and safety gates.

05 · Failure modes

Error Reference

Most failures come from invalid payloads, missing auth, wrong entity IDs, Home Assistant being offline, or token/URL mismatch during PC ↔ Orin cutover.

StatusCauseResolution
400Invalid JSON, unsupported action, out-of-range brightness.Validate request body and action name. Brightness must be 0–255.
401Missing or invalid Home Assistant token.Regenerate HA Long-Lived Access Token and update HA_TOKEN.
403Token lacks permission or HA blocks the action.Use an admin token or check Home Assistant user permissions.
404Entity or route not found.Check HA Developer Tools → States for the real entity_id.
503Home Assistant unreachable, starting, or wrong HA_URL.Check Docker/container status, LAN IP, port 8123, and backend env vars.

06 · Operator snippets

Code Examples

Turn a light on with brightness from curl, Python, or JavaScript. Replace the entity ID with your real HA entity when hardware is paired.

curl
curl -X POST http://127.0.0.1:8000/devices/light.mock_bedroom_lamp/turn_on \
  -H "Content-Type: application/json" \
  -d '{"brightness":180,"require_verification":true}'
python
import httpx

payload = {"brightness": 180, "require_verification": True}
response = httpx.post(
    "http://127.0.0.1:8000/devices/light.mock_bedroom_lamp/turn_on",
    json=payload,
    timeout=10,
)
response.raise_for_status()
print(response.json())
javascript
const response = await fetch("http://127.0.0.1:8000/devices/light.mock_bedroom_lamp/turn_on", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ brightness: 180, require_verification: true })
});

if (!response.ok) throw new Error(`API failed: ${response.status}`);
console.log(await response.json());
